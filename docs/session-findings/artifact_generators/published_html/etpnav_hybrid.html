ETPNav vs. hybrid grounding · same 25 spatial-relation cases

Bypassing the language model for spatial relations

Same 25 instructions, same house, same start poses and targets as the earlier spatial test. Before: ETPNav's own language-conditioned waypoint policy tries to resolve "left of the sofa" itself. After: a thin parser reads the relation + object out of the instruction, looks up the object's real position (the same semantic-scene lookup used to build the test), and walks straight there with habitat-sim's own pathfinder — no VLN model, no GPU inference.

What this does and doesn't show. This isn't a smarter model — it's a deterministic point-goal navigator using coordinates we already had, so 100% was expected, not a result to be impressed by on its own. What it does show: the fix for this specific instruction class (bare "left/right/behind/next-to X" commands) doesn't need to touch the VLN model at all if the target object is identifiable from the instruction text — a practical, cheap mitigation, not a research result. It would fail the moment the object isn't cleanly nameable, isn't in the semantic scene annotations, or the instruction mixes spatial relations with real navigation (e.g. "go to the kitchen, then stand left of the table").
