Does rephrasing fix spatial instructions?

Four instructions that clearly missed their target in the earlier spatial-relation test, each rerun with five phrasings — same house, same start pose, same computed target — from a bare command up to a fully narrated, R2R-style instruction. Only the wording changes.

What we found

Rephrasing barely moved the needle. For 3 of the 4 cases (sofa/right, dresser/behind, bookshelf/next-to), final distance-to-target is identical to two decimal places across all five phrasings — the bare command and the fully narrated, explicit-stop-cue version land the agent in the same spot. The one case with any spread (table/left, 3.47–5.33m) shows no consistent trend: the two mid-length phrasings did best, but the longest, most explicit "narrated" version was no better than the bare command. That rules out "make the instruction longer/more explicit" as a fix on its own.

  • The model gets to the right neighborhood, not the right side. All four cases land within ~5–13m of a target that's only ~2–3m from the object — it's finding the landmark's general area (visible in the videos) but not resolving "which side." R2R/RxR training instructions almost never ask an agent to stop at a specific offset from an object's left/right/behind; the model likely never learned that distinction, so no phrasing recovers it.
  • Bookshelf/next-to did respond to phrasing in path shape, not outcome. Step count dropped from 101 (bare) to 32 (two-step) and path length from 13.2m to 4.8m — the more direct phrasings clearly changed how it moved — but it still ended up roughly the same distance from our target, just via a shorter route to a different wrong spot.
  • Dresser/behind surfaced a second, unrelated failure mode: a deadlock. All five phrasings took 210+ steps to cover a net 1.68m, with a collision rate over 10 — the agent is stuck oscillating against an obstacle near the start, not failing to understand "behind" at all. This is the same deadlock behavior the ETPNav paper documents for its Tryout controller (§4.3.4, Fig. 6) under sliding-forbidden conditions — a control/obstacle-avoidance failure, not a language one, and phrasing was never going to fix it.

Net read: the 8% pass rate isn't primarily a prompt-clarity problem. It's the topological waypoint/ghost-node planner weighting visual/structural priors (open doorways, room layout) over fine-grained language for close-range positioning it was never trained to resolve — plus, at least once here, a genuine control-layer deadlock unrelated to language at all.
